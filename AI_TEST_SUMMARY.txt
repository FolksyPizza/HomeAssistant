HOW IT WORKS
================================================================================

The test script:

1. Generates synthetic audio files programmatically
   - Silence (pure quiet 1-second audio)
   - Tones (sine wave at 440Hz for 2 seconds)
   - Speech (via espeak if available)

2. Encodes audio as base64 and sends via JSON API
   - No CSRF issues (not form-based)
   - Programmatic API access
   - Suitable for CI/CD automation

3. Receives transcription results from Whisper
   - Audio decoded by application
   - Processed by whisper.cpp
   - Transcript returned as JSON

4. Validates TTS provider availability
   - Checks Piper status
   - Would generate audio on Pi hardware
   - Confirms text-to-speech is configured

TECHNICAL DETAILS
================================================================================

API Endpoint: /api/assistant/transcribe-test
  - Method: POST
  - Content-Type: application/json
  - Body: {
      "audioBase64": "base64-encoded WAV data",
      "audioFileName": "optional filename",
      "browserTranscriptHint": "fallback text"
    }
  - Response: {
      "transcript": "transcribed text",
      "provider": "local-whisper|mock-browser-hint",
      "audioSeconds": number
    }

Audio Generation:
  - Silence: numpy array of zeros
  - Tones: sine wave calculation
  - Speech: espeak command-line tool

Transcription:
  - whisper.cpp CLI invocation
  - 16-bit mono WAV format
  - Automatic format conversion via FFmpeg

TTS:
  - pi_voice_bridge.py helper script
  - Piper text-to-speech engine
  - ONNX runtime for inference
